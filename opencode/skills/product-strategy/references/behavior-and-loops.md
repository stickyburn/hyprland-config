# Behavior and Loops

Use for activation, onboarding, retention, behavioral interventions, and
growth loops. Start with observable value, not a goal like “more engagement.”

## Behavior and Intervention

Define: a specific user takes an observable action at a real trigger because
it produces progress. Identify the demonstrated barrier: ability, access,
opportunity, effort, uncertainty, risk, or coordination. A reminder cannot
solve missing permissions; a streak cannot create recurring value.

For an intervention, specify the behavior/context, evidence for the barrier,
mechanism, user benefit, likely failure, behavior metric, guardrail, and test.
Do not attach universal lifts to defaults, framing, or social proof. Popular
UI patterns and observed correlations need causal validation in this setting.

## Activation and Retention

Activation should predict realized value, not just be easy to count. Compare
retained/churned cohorts before declaring an “aha moment”; inspect time to
first value, setup prerequisites, empty states, and whether users can assess
quality early. Buyer and user may experience value at different times.

Segment retention by natural cadence and cause. Does value repeat, accumulate,
or conclude? Distinguish lack of activation, voluntary/payment churn,
seasonality, role changes, and implementation failures. Identify the alternative
that regained the job. Do not force daily use for an episodic or weekly task.

## A Loop Must Close

```text
trigger -> action -> user value -> changed state/artifact -> qualified re-entry
```

Identify the entry source, value-producing action, output, recipient of the
next trigger, conversion and cycle time at each edge, and saturation/abuse risks.
Distinguish recurring usage, distribution to qualified people, and revenue
that funds further value. A notification schedule, referral button, or funnel
is not a loop unless one cycle's output becomes the next cycle's input.

Example: shift supervisors receive yesterday's unresolved safety issues in
their existing handoff channel; resolving an issue changes the next handoff.
Compare resolution within a shift while monitoring muted notifications and
false closures. This is more useful than generic daily streaks and reminders.

## Trust and Validation

Reject hidden costs, confusing consent, coercive streaks, fake scarcity,
fabricated proof, cancellation obstruction, and disproportionate friction
for export, deletion, or privacy controls. Notifications should help at a
real trigger, not merely reclaim attention.

Check whether an informed user would choose the intervention, understand it,
and be able to decline/reverse it. Measure user benefit as well as business
outcome, with complaints, regret, notification muting, and long-term retention
as relevant guardrails. Set proposed thresholds and time limits explicitly;
change the recommendation when results fail them.
